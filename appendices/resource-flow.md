# 资源关系：一份数据从哪里来，又被谁使用

[返回目录](../README.md) · [三张总览图](../chapters/00-frame-overview.md) · [源码索引](source-index.md)

> 本表从 UE 5.7.4 教材配置 A 的**概念级资源导航**开始，再补充现代功能的资源分支。它不是本机 GPU 抓帧，不规定统一纹理格式、分辨率、分配数量或唯一执行顺序。一个表项可能对应多个实际资源；对应章节已按所选分支说明布局与条件。

## 先区分三件事

**资源的含义**回答“这里保存什么”；**资源的生产者与消费者**回答“谁写、谁读”；**资源的生命周期**回答“何时可以创建、复用和结束使用”。只知道名字不能回答全部问题。

例如深度既可以用于确定后续表面的可见关系，也可用于重建位置或形成分层深度。某个 Pass 读取深度，并不表示它也会改变深度；某个字段引用了纹理，也不表示这张纹理在每种配置下都已分配并写入有效数据。

## 主要数据与连接

| 数据或资源 | 保存什么 | 主要生产者 | 典型消费者 | 本批必须保留的条件 |
|---|---|---|---|---|
| 顶点与索引数据 | 几何位置、属性及图元引用关系 | 网格资产处理与相应资源建立 | 普通网格的几何绘制，包括适用深度与阴影工作 | 可复用，不是每帧必须从磁盘重建；Nanite 有另一套相关表示 |
| 物体变换与实例数据 | 模型摆放、实例差异等信息 | 游戏侧更新及渲染场景更新路径 | 可见性、顶点相关处理、实例绘制 | 更新与消费存在同步和所有权约束 |
| 视图相关数据 | 相机、投影、当前与历史观察信息 | 视图准备 | 几何处理、位置重建、光照、后处理 | 主相机、阴影和捕获可能用不同视图 |
| Scene Depth | 当前主视图相关深度结果 | 适用 Prepass 和／或 Base Pass 等深度写入 | 深度测试、HZB、位置重建、SSR、部分后处理 | 本例普通透明薄片不作为主不透明深度；深度值不是米 |
| HZB | 多层分辨率的深度摘要 | 从可用深度生成层级的工作 | 适用遮挡与屏幕空间算法 | 可在不同深度完成时机生成，某些使用者消费的是历史结果 |
| DBuffer | 适用贴花的表面修改数据 | Base Pass 前的 DBuffer 贴花 | 适用材质的 Base Pass | 本章场景没有贴花；此项不表示基础案例必然执行 |
| GBuffer | 编码后的表面法线、材质属性等 | Base Pass 与适用的后续贴花修改 | 延迟光照、适用反射和其他效果 | 传统布局与 Substrate 布局不能无条件互换；不是每属性独占一纹理 |
| 阴影深度及派生结果 | 光源相关可见性与遮挡信息 | 阴影深度绘制及相应过滤、投影等步骤 | 受光表面的阴影判定 | 与相机深度不同；常规贴图、VSM、光追阴影不是同一种数据 |
| HDR Scene Color | 当前已经形成的场景颜色贡献 | Base Pass 的适用初始贡献、光照、反射、合成等 | 透明相关合成、时序与后处理、后续输出 | 可能有预曝光缩放；不是一开始就完成，也不等于窗口 Back Buffer |
| SSR 相关结果 | 屏幕空间反射求得的可用贡献与相关信息 | SSR 追踪与适用重建处理 | 场景反射合成 | 取决于方法、强度、质量、粗糙度和有效视图信息 |
| 透明颜色等资源 | 透明表面自己的着色贡献 | 适用透明绘制阶段 | 与背景合成的位置及部分后处理 | 可以先写单独目标；并非总直接写主 Scene Color |
| Velocity | 供时间相关处理使用的运动信息 | 当前配置下适用的速度写入路径 | TAA／TSR、运动模糊等 | 写入阶段受配置影响；还要结合相机与历史信息解释 |
| 历史资源 | 之前选定帧留下的颜色、深度或其他结果 | 相应系统在结束使用当前结果后保留 | 后续帧的时间处理、重投影与适用遮挡 | 不是一个包办所有系统的“历史纹理”；新视图或相机切换等可能使历史失效 |
| 最终场景输出 | 完成相应后处理后的视图结果 | 后处理链的适用输出阶段 | 窗口、UI 合成或离屏使用者 | 场景捕获未必 Present；游戏主视图也不代表已物理显示 |
| 交换链后备缓冲 | 准备用于窗口呈现的图像 | 窗口与场景输出等相关绘制 | 呈现系统 | 还存在 GPU 完成、提交呈现与显示扫描之间的边界 |

这里使用“典型消费者”而不是“全部消费者”，因为深度和场景颜色等共享资源会被大量配置分支使用。详细章节继续核对每个消费者的条件。

## 用 P 与 Q 检查是否把资源含义读错

P 与 Q 的定义来自 [第一章](../chapters/01-from-scene-to-pixel.md)：P 是未被薄片覆盖的红方块表面；Q 是蓝色薄片覆盖方块的位置。

1. 在主不透明深度里，本例 P、Q 都先关联到方块，而不是 Q 自动改存薄片深度。
2. 在传统不透明 GBuffer 中，Q 的背景属性仍需要存在，才能解释后面的背景颜色；薄片不是把方块属性平均成一种新材质。
3. 在透明合成前后的相关颜色结果中，Q 的颜色可发生改变；这种变化不能倒推为“方块的 Base Color 已经变了”。
4. 当读取历史结果时，必须知道对应的帧和视图。相同屏幕坐标上一帧可能不是同一个表面。
5. 在窗口后备缓冲看到已经合成的图像，不代表每个最终像素能反推出唯一的材质输入；多个因素已经组合。

以上判断针对本章明确的普通无光照透明材质。不把写入自定义深度、特殊透明效果或其他材质模式悄悄加入，再沿用同一结论。

## 怎样用源码核对这张表

**[源码已确认]** [SRC-SCENE-TEXTURES](source-index.md#src-scene-textures) 对照 `FMinimalSceneTextures`、`FSceneTextures` 和 `FGBufferData`，可以确认颜色、深度、GBuffer 与速度的不同入口，但结构成员不能自动翻译为实际纹理通道。

**[源码已确认]** [SRC-BASEPASS](source-index.md#src-basepass) 给出材质参数读取、输出到多个渲染目标，以及延迟光照读取表面结果的连接。MRT（Multiple Render Targets，多渲染目标）允许一次绘制写多个目标，不代表一次写入就完成所有光照。

**[源码已确认]** [SRC-RDG](source-index.md#src-rdg) 提供图执行入口。检查资源生命周期时，应继续追踪创建、读写声明、跨帧提取与外部访问；不能用 C++ 局部变量离开作用域的时刻，替代 GPU 最后一次访问完成的时刻。

**[教学简化]** 本表不是内存占用报告。计算内存时还要核对尺寸、格式、采样数、层数、驻留范围、临时资源复用和历史保留，不能把每行都算成一张永久存在的 1280×720 四通道纹理。

## 基础篇的进一步解释

[第 05 章](../chapters/05-resources-color-history.md) 将本表展开为可计算的例子：RGBA16F 数据量、纹理过滤、视口 UV 到缓冲 UV、sRGB 编解码、预曝光尺度以及 TAA 历史登记和提取。它补齐“资源存在”到“读到正确数据”之间的条件，但仍不把这些理论估算当作运行内存或带宽测量。

[第 09 章](../chapters/09-rdg.md) 继续解释这些资源如何成为图中的生产消费关系：参数访问声明、RAW／WAR／WAW、无用 Pass 裁剪、使用区间、瞬态复用和图外历史。其真实 TAA 路线把资源声明与计算调度连接起来，明确图对象、RHI 对象和 GPU 使用具有不同寿命。

## 场景记录与深度的进一步解释

| 资源／记录 | 生产与消费 | 章节与边界 |
|---|---|---|
| GPU primitive／instance 数据 | 场景脏更新 → 上传准备 → 散布写入 → Shader 索引读取 | [第 11 章](../chapters/11-scene-visibility.md)；只更新脏记录与全量调试上传不同 |
| 实例 ID 与间接计数 | CPU 绘制组织提供描述 → 适用 GPU 实例筛选写入 → Draw 消费 | [第 12 章](../chapters/12-mesh-draw-commands.md)；筛掉一次绘制不等于删除 GPU Scene 记录 |
| 主深度 | Depth Shader 写入 → 适用 Base Pass 深度访问与 HZB | [第 13 章](../chapters/13-depth-prepass-hzb.md)；完整预通道不使所有 Base Pass 一律 Equal |
| 当前／历史 HZB | 当前深度归约 → 当前消费者；条件提取 → 后续适用消费者 | HZB 可因 SSR 等需求生成，提取不是 CPU 读回 |
| HZB 测试结果纹理 | 包围体中心与范围上传 → GPU 每项测试 → Readback → CPU 历史消费 | 结果纹理的像素代表一项测试，不代表同坐标的主视图像素 |

[第 10 章](../chapters/10-rhi-d3d12.md) 解释这些图内访问如何继续成为 D3D12 的原生命令、描述符、资源屏障和队列同步。资源可被 Shader 访问、命令已经提交、CPU 可读回和屏幕已经显示是不同条件。

## 从表面属性到光照颜色

| 资源 | 生产与消费 | 章节与边界 |
|---|---|---|
| DBuffer A／B／C 及 Mask | 适用贴花投影写入 → Base Pass 接收方读取并合入材质输入 | [第 14 章](../chapters/14-base-pass-gbuffer-decals.md)；普通 Translucent 蓝片排除于自动应用分支 |
| 传统 GBuffer | 材质求值 → 生成编码写 MRT → 光照／反射按对应布局解码 | 实际法线格式和 sRGB 标志有条件；属性不整体乘预曝光 |
| 常规二维／点光阴影深度 | 光源相关视图绘制 → 屏幕接收点重建／比较／PCF | [第 15 章](../chapters/15-shadows.md)；二维 LessEqual／清 1 与点光反向 Z 不混用 |
| Screen Shadow Mask | 对当前灯投影阴影与适用效果 → 当前灯读取衰减通道 | 生成阴影深度与投影遮罩分开，遮罩可复用存储，不能保留旧灯含义解释下一灯 |
| Deferred Light Uniform | Proxy／CPU 参数转换 → Shader 灯光数据 → BRDF、范围和阴影计算 | [第 16 章](../chapters/16-direct-lighting.md)；Add 混合把当前灯贡献累加至预曝光颜色 |
| ScreenSpaceAO | 当前邻域采样 → AO 合成已有颜色及适用其他消费者 | [第 17 章](../chapters/17-indirect-ao-reflections.md)；A 的 AO 合成先于直接光照，不是最终颜色统一变暗 |
| SSR 颜色输入／结果 | 有效历史或当前颜色 → 当前深度搜索 → 反射贡献／可信权重 → 材质响应与合成 | 使用 TAA 历史颜色不等于额外运行 SSR 时间滤波；SSRHistory 与 TemporalAAHistory 不同 |

以上表中的先后关系是相应读写依赖。CPU 构图顺序、RDG 回调、底层提交和 GPU 执行仍按第 08～10 章区分。

## 透明、历史、显示与 Substrate

| 资源 | 生产与消费 | 章节与边界 |
|---|---|---|
| Separate 透明颜色／Alpha | 清 RGB=0、A=1 → 透明层积累贡献 D 与透射率 T → D+T×背景 | [第 18 章](../chapters/18-translucency-sky-fog-volume.md)；合成时不能再次把 D 乘覆盖率 |
| 体积雾 LightScattering | 体素光照／适用历史混合 → FinalIntegration → 累计散射与透射 | 历史发生在最终积分前；颜色曝光修正不应同样施加给消光 |
| 原始 Velocity 与相机矩阵 | 适用速度 Pass／Base Pass 写入 → 消费者结合深度恢复相机运动 → 重投影 | [第 19 章](../chapters/19-velocity-taa-tsr.md)；静态表面原始速度清值不保证屏幕位置不动 |
| TSR Guide／Color／Metadata 历史 | 拒绝和更新阶段产生 → 提取保留 → 下一帧比较与重建 | Guide 不等于高频颜色；输出还可放入 TemporalAAHistory 供 SSR 消费 |
| 曝光数据／颜色 LUT | 适用手动或统计曝光计算；颜色分级生成 LUT → Tonemap 消费 | [第 20 章](../chapters/20-postprocess-present.md)；无用户 LUT 不等于没有内部 LUT |
| 场景输出／窗口 Back Buffer | 场景后处理输出 → 适用 Slate 视口元素与 UI → 交换链呈现 | 离屏纹理、窗口缓冲、Present 请求与实际扫描显示有不同生命周期 |
| Substrate Blendable GBuffer | 材质拓扑求值 → 导出 GBuffer → SubstrateReadGBufferBSDF 重建 | [第 21 章](../chapters/21-substrate.md)；B 的延迟光照不固定读取 Adaptive Material Container |
| Substrate 材质分类列表 | GBuffer／适用材质信息 → 每 8×8 Tile 分类 → 分类绘制与调度 | 单个主类别不排除辅助列表；B 仍分配、消费适用分类资源 |
| Adaptive Substrate.Material | 平台及预算确认 → 条件分配数组 → Header／Closure 打包 → 适用消费者 | 仅作独立格式对照；Blendable B 不创建这一 Adaptive 数组 |

跨帧历史保留是资源引用与同步问题，不是把 GPU 纹理转成 CPU 数组。颜色表示也必须沿链路追踪：SceneColor 的预曝光值、透明透射率、LUT 输入和显示编码不能因都使用 RGB／RGBA 就直接互换。

## 现代功能的几何与缓存

| 资源 | 生产与消费 | 章节与边界 |
|---|---|---|
| Nanite 页面与层级 | 构建期编码 → 根页与流送请求 → 安装／转码 → GPU 层级选择 | [第 22 章](../chapters/22-nanite.md)；请求不等于本帧立即驻留 |
| Nanite VisBuffer | Main／适用 Post 光栅竞争 → 深度与遮罩导出 → 材质分桶重建输入 | 材质 CS 与条件 Compute 深度导出分开，辅助 lane 不都写结果 |
| VSM 请求／页表／物理池 | 接收者需求 → 复用／分配／失效 → 清页与阴影光栅 → 虚拟查询 | [第 23 章](../chapters/23-virtual-shadow-maps.md)；普通网格也可向物理 UAV 写反向 Z |
| VSM 静态／动态层 | 缓存分类与更新 → 适用分离深度 → max 合并 → 投影消费 | Receiver Mask 可让动态部分 uncached，静止不保证所有页全缓存 |
| One Pass mask bits | 局部灯一起投影／打包 → 每灯查找 → 超预算单样本回退 | 不替代每灯虚拟深度生成，也不等同 clustered deferred |
| Lumen SDF 与卡片 | 几何资产构建 → 距离场／卡片维护 → 软件求交 → 卡片光照采样 | [第 24 章](../chapters/24-lumen-software-tracing.md)；求交与得到出射亮度分开 |
| Lumen Final Lighting | 卡片直接／间接辐照度与 Albedo／Emissive → 组合 → 持久光照反馈 | 更新预算不是固定每 N 帧更新所有页 |
| Screen Probe／Radiance Cache | 当前需求和历史 → 方向追踪／滤波 → 积分与像素合成 | 空间探针、表面缓存和屏幕像素历史各有独立表示 |
| BLAS／TLAS | 实例收集、适用几何更新 → 结构构建 → 光线 Shader 遍历 | [第 25 章](../chapters/25-hardware-ray-tracing.md)；按层／视图组织，存在维护成本 |
| Lumen HWRT TraceRadiance | 屏幕后待处理项 → 硬件求交 → 缓存／命中光照 → 反射重建 | 切换几何查询不自动省略 Lumen 历史或改用 Path Tracing |
| MegaLights 样本与历史 | 灯光概率／历史引导 → 阴影查询 → 样本着色 → 时间／空间处理 | 采样可提前影响 VSM 页面请求；光照历史不是主 TAA History |

## 把资源表接回一帧

[第 26 章](../chapters/26-basic-frame-walkthrough.md) 将配置 A 的 P/Q 逐步记账：普通深度、传统 GBuffer、不透明光照、独立透明 D/T、TAA 当前结果与图外历史，再到 View 输出与窗口。颜色必须注明是否预曝光；透明 Alpha 必须注明是覆盖率还是背景权重。

[第 27 章](../chapters/27-modern-frame-walkthrough.md) 对配置 B 增加几何引用、Blendable 布局、VSM 页状态和多种 Lumen 历史。主像素、灯光投影视图、卡片 texel 与空间探针不是同一个采样位置；各自缓存的更新年龄也不必相同。

阅读笔记可统一记录：`资源名 | 格式/尺寸/ViewRect | 写入者 | 读取者 | 表示与单位 | 有效性 | 图内寿命或图外持有者`。只有真实捕获后才能填“本帧执行过”；静态源码记录应保留条件，而非将所有可能生产者并列成一次执行。
