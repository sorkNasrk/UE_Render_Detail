# 第 06 章参考答案：Actor、Component 与渲染场景表示

[返回第 06 章](../../chapters/06-scene-representation.md) · [返回目录](../../README.md)

答案沿用 UE 5.7.4、配置 A 的范围。涉及实际场景分支的判断均以正文已读源码为依据，计数与几何计算属于教学模型，没有运行测量结果。

## 题 1：游戏组织、几何与灯光分别表示

Actor 负责游戏身份和组件组织；普通 Scene 根组件提供附着与变换，本身不要求有可见网格。两份 Static Mesh Component 分别保存各自摆放与覆盖设置，但可共享同一 Cube 资产的几何资源。

在本章两个网格都有效、需要加入场景且普通代理创建成功的前提下，它们分别形成自己的 `FStaticMeshSceneProxy` 与 `FPrimitiveSceneInfo`。点光通过 `FLightSceneProxy` 与 `FLightSceneInfo` 进入照明管理，不是第三份 Cube 几何代理。表示是否实际存在仍受可见用途、资产就绪和有效强度等条件影响。

Draw Call 数要继续看网格 Section、当前 LOD、适用 Pass、视图、剔除与合并。灯光对像素的处理也不能等同于一次网格对象绘制。因此 Actor 数、代理数与 Draw Call 数不能互相替代。

## 题 2：范围与变换必须相配

原半边长为 `(50,50,50) cm`。沿 Y 移动 +60 cm 后：

```text
新中心：(0,-60,50) cm
X 范围：[-50,50] cm
Y 范围：[-110,-10] cm
Z 范围：[0,100] cm
```

局部顶点可以不变，由新矩阵完成世界摆放；但可见性和空间管理如果仍使用旧 Bounds，就可能把新位置的几何当作旧区域中的对象，出现错误筛选或关联。因此变换更新同时携带包围体具有实际必要性。

本章运行时移动实验先将测试 `UStaticMeshComponent` 设为 **Movable**。本地 `ShouldRecreateProxyOnUpdateTransform` 对非 Movable 返回 true，因此不能把其他移动性下的重建行为当作增量路径的反例，也不能只根据 Static Mesh 名称判断是否能移动。

## 题 3：数据更新与表示重建

修改已赋给组件的同一个 MID 的普通 Roughness 标量，会更新实例参数，值变化后通过命令把参数信息与值交给 `FMaterialInstanceResource`，使统一表达式缓存失效并刷新。正文核对的这条路径不标记 primitive 渲染状态重建，也不等同于重新编译 Shader。

向组件 SetMaterial 一个不同材质，则更新材质槽覆盖，触发 PSO 预缓存并调用 `MarkRenderStateDirty`。它可能改变材质相关性和所需程序，所以采用渲染表示重建路线。第一次创建 MID 并赋给组件仍属于这种材质替换，与以后只改该 MID 数值不同。

本例 Movable 点光从 800 lm 改为 1200 lm，已有代理且有效强度条件不变，可走颜色亮度增量更新。若强度改变使光需要加入或退出场景，路线又可能变成状态重建。不同单位的有效性判断还有差异，不能把流明示例推广为所有单位下的规则。

“参数”只描述用户看到的输入，不说明内部影响。应检查具体 setter、资源布局和场景成员关系是否变化。

## 题 4：先解除关联，再完成受控清理

不一定是泄漏。组件侧的代理指针清空，表示它不再以旧代理作为当前关联；渲染侧已排队工作仍可能需要旧表示活着。

普通路径保存旧 Proxy／SceneInfo，排入移除命令；命令登记删除并处理渲染资源撤销；`FScene::Update` 汇总变更并移除适用记录，随后通过清理任务删除旧表示。编辑器 Hit Proxy 引用还被转交独立的延迟清理对象。应检查这条链是否最终完成，而不是要求指针清空与内存释放同时发生。

默认 `DetachFence.BeginFence` 使用 RenderThread 同步深度，用于跟踪相关渲染线程边界，并参与组件可否完成销毁的判断。它不是“所有 GPU 工作已经完成”的全局证明；GPU 资源在途引用和后端释放还由对应机制处理。

## 题 5：身份稳定性与线程访问是两类问题

第一类是标识失效：`PackedIndex` 是场景紧凑数组的位置，其他 primitive 加入或移除时也可能变化。跨组件重新注册识别同一个组件，应考虑 `PrimitiveComponentId`；若仅跟踪一次 Proxy／SceneInfo 场景驻留期间的记录，可按对应接口使用 PersistentIndex。两种稳定范围仍不同，不能任意跨生命周期复用。

第二类是访问竞争和对象寿命：渲染回调解引用组件可变材质数组时，游戏线程可能正在修改、扩容或销毁它。指针非空不证明当前访问安全，选对 ID 也不会自动解决线程同步。

应在允许访问组件的阶段取得需要的值，通过已有接口或遵守契约的命令交接到渲染侧表示，并保证所引用资源活到使用结束。渲染侧用代理与受控资源完成收集，不能把调试用组件地址当作任意读取游戏状态的入口。
