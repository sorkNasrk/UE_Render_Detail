## 题 1：从必要输出保留生产链

E 写入图外需要的 Output；E 需要 C 和 D，C 需要 B，B 和 D 都需要 A，因此保留 A、B、C、D、E。D 的外部 History 作为输入参与访问管理。

X 只产生没有消费者、没有提取或其他保留理由的临时预览，本例中可以裁剪。若提取该预览供图外使用，X 成为必要生产者，其依赖 A 也必须保留。主画面是否变化不是判断图外输出是否必要的唯一依据。

## 题 2：描述、记录与完成

`CreateTexture` 建立图资源描述；`AddPass` 登记参数、标志和工作回调，普通模式下不立即运行 GPU 工作。`Execute` 处理图并组织回调、命令列表和提取等步骤，但正常返回不保证全 GPU 空闲。

GPU 写入完成是相应命令真正执行到满足同步条件之后的事件。若 CPU 需要使用结果，必须有相应读回与完成保证。

构图函数局部数组在函数返回后可能已销毁，而 Lambda 延迟执行。捕获其引用将造成失效访问；仅按值捕获一个指向该数组的指针也不能修复底层数据寿命。

## 题 3：复用需要没有冲突的使用区间

```text
单张 = 640*360*8 = 1,843,200 字节
单张 MiB = 1,843,200 / 1,048,576 = 1.7578125 MiB
两份 = 3,686,400 字节 = 3.515625 MiB
理想减少一份 = 1,843,200 字节 = 1.7578125 MiB
```

这是忽略对齐、平台元数据和其他限制的基础数据估算。D 若仍读取 U，而同时写 V，直接覆盖共享存储可能破坏尚未使用的 U 数据；原来的不重叠区间前提已经改变。

## 题 4：先检查具体标志，再检查支持条件

不能断言。对应重载默认传入 `ERDGPassFlags::Compute`，不是 `AsyncCompute`。政策值 1 允许已标记为异步的工作，仍受硬件、调试模式、平台和图条件限制；注册值、当前值与实际路径也不能互换。

CPU 并行记录说明多个 CPU 任务可以同时产生命令。GPU 上仍可能因生产消费关系顺序执行；两者不能互相当作证据。

## 题 5：向上取整与图外持有

```text
X 组数 = ceil(1001/8) = 126
Y 组数 = ceil(601/8) = 76
Z 组数 = 1
总组数 = 126*76 = 9,576
调用覆盖 = 1008*608 = 612,864
有效目标像素 = 1001*601 = 601,601
超过矩形的调用 = 11,263
```

Shader 需要以有效矩形判断写入范围；若涉及组内同步，不能简单让部分线程在同步前随意退出。真实 TAA 主输出有相应坐标与边界判断，其他输出或变体仍需分别检查。

资源提取保存的是图外可持有的纹理引用，使后续 GPU 工作可继续使用。它不是像素下载，也不自动证明 GPU 写入已经完成。CPU 读取像素还需要读回资源、复制及合适的同步。
