## 题 1：基础像素数据量

RGBA16F 的基础数据是每像素 `4×16/8=8` 字节，因此：

```text
640 × 360 × 8 = 1,843,200 字节
1,843,200 / 1,048,576 = 1.7578125 MiB
```

这个算式没有包含资源对齐、元数据、其他子资源、堆分配和实际驻留规则。它能解释理想数据量，不能替代平台实际内存测量。

## 题 2：控制数据与颜色编码

粗糙度 `0.5` 是已经按算法约定保存的控制值。错误地按 sRGB 解码会将其变为约 `0.214`，直接改变材质响应，并非只改变预览显示方式。

如果一张 Base Color 纹理的 RGB 确实采用 sRGB 编码，则需要在相应采样路径中正确解码后参与线性计算。两种设置都由内容与语义决定，不是统一开或统一关。

## 题 3：视口 UV 到缓冲 UV

```text
PixelInBuffer = (200,100) + (0.4,0.6) × (1000,500)
              = (600,400)

BufferUV = (600,400) / (2000,1000)
         = (0.3,0.4)
```

直接用 `(0.4,0.6)` 读取整张缓冲会访问不同位置。此题使用连续坐标模型，没有额外引入像素中心取整。

## 题 4：先校正历史表示，再组合

```text
H_corrected = 3 × 0.02 / 0.03 = 2
C_result = 0.6 × 2 + 0.4 × 2.5 = 2.2
```

比值方向是“当前尺度／历史尺度”。如果不校正而直接混合，会得到 `2.8`；这个数把不同表示的值混在一起。权重 `0.6` 是题目假设，不是 UE 的固定 TAA 默认权重。

## 题 5：历史引用不足以证明历史可用

登记外部纹理解决的是把已经由图外持有的资源纳入当前图的使用。视图矩形和尺寸决定从哪里寻找对应；历史有效性判断防止使用缺失或不适用的结果；曝光校正将颜色转换到一致尺度。它们回答不同问题。

`QueueTextureExtraction` 将相应结果交给图外持有，以便之后继续使用。它不是 GPU 到 CPU 的像素读回，也不是写文件。需要读回时还会涉及另外的数据传输与同步步骤。
