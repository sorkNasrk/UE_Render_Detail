# 第 20 章答案：后处理、颜色输出与 Present

[返回本章](../../chapters/20-postprocess-present.md) · [返回目录](../../README.md)

## 题 1

`EV100=log2(4^2*60*100/100)=log2(960)≈9.907`。快门倒数 60 表示 1/60 秒。

在适用桌面曝光条件下，补偿加一档使补偿倍率乘 2；快门倒数从 60 加倍到 120 则使物理 EV100 增加 1，在其他条件相同时曝光倍率减半。曝光补偿与物理相机 EV100 不是方向相同的控制量。准确倍率仍须包含亮度标定、开关与最终 View 参数。

Manual 固定曝光选择，不取消 Tonemap、输出编码或 TAA，也不让 Unlit 蓝片绕过曝光。

## 题 2

```text
Cs = (8,2,1)*0.25 = (2,0.5,0.25)
Ce = Cs*(0.125/0.25) = (1,0.25,0.125)

若 p=0.5：
Cs = (4,1,0.5)
Ce = Cs*(0.125/0.5) = (1,0.25,0.125)
```

预曝光存储值改变，但生产与消费使用匹配倍率，目标结果保持相同。这里没有包含 Tone Curve、颜色分级、暗角、Bloom 和局部曝光，不能当最终显示 RGB。

本版 `UpdatePreExposure` 的 Manual 分支直接使用当前固定曝光；自动方法才读取已有有效 Last Exposure。缺少 ViewState、调试视图和覆盖变量也有不同处理，所以不能把“总是上一帧曝光”当成通用公式。

## 题 3

对数平均为 `(0+4)/2=2`，还原为 `2^2=4`。算术平均为 `(1+16)/2=8.5`。该例假设等权正亮度，没有裁剪、测光遮罩、下采样和量化影响。

Histogram 按亮度桶的累计权重保留低、高百分位之间的部分，对保留的对数亮度加权。它可减少指定亮度分布两端的影响，不等于删除固定屏幕区域。最终曝光还要经过范围、补偿和时间适应。

桌面代码在 Manual 下也可能添加 Histogram Eye Adaptation Pass，以固定范围处理并输出曝光数据，即使未生成实际直方图。事件名称不能替代对方法和输入条件的检查。

## 题 4

配置 A 的 Bloom Intensity 与质量为 0，因此亮自发光并不自动生成 Bloom。景深质量为 0，虽然 F-stop 仍参与物理曝光，也不会据此启用 DOF。运动模糊 Amount 与质量为 0，Velocity 或物体移动并不足以启动该效果；开启后还需满足显示标志、实时更新、有效历史等条件。

单独启用 Bloom 后，亮部经适用准备、下采样与模糊或卷积，再作为颜色贡献合成。Q 附近的扩散可能影响 P 的显示颜色，但没有因此改变 P 的世界空间入射光、GBuffer 或灯光列表。实际是否观察到扩散仍取决于方法、强度、阈值与覆盖。

## 题 5

Tonemap 输出属于场景 View，可能还要缩放、合入其他视图或显示为 Slate 视口纹理。窗口 UI、HDR UI 合成等可以继续修改窗口输出，所以它不必等于整个交换链 Back Buffer。

普通路线为：场景视图输出与 Slate 窗口元素 → `PresentWindow_RenderThread` → `RHICmdList.EndDrawingViewport` → D3D12 `RHIEndDrawingViewport` → 视口 `Present`/`PresentChecked` → Windows `PresentInternal` → `SwapChain1->Present`。无效视口、禁止呈现或 CustomPresent 可以改变或跳过原生分支。

Present 返回表示对应调用返回，可能已经包含某些等待，但不能精确证明面板完成显示。GPU Fence 只证明其作用范围内的 GPU 工作达到完成条件。人眼可见还涉及系统呈现调度、适用桌面合成、刷新和面板响应。等待提交线程也不同于等待 GPU，更不同于测量显示器。
