# 第 10 章答案：RHI、D3D12 与呈现

[返回本章](../../chapters/10-rhi-d3d12.md) · [返回目录](../../README.md)

## 题 1：分层执行与完成

RHI 命令 `Execute` 在 CPU 上将记录的引擎操作转交后端上下文。原生 `DrawIndexedInstanced` 调用将绘制记录到 D3D12 命令列表。上下文 `Finalize` 结束适用记录，汇总列表、同步与回收责任，形成平台工作。

`ExecuteCommandLists` 把已关闭列表提交给设备队列。上述步骤都是 CPU 组织、记录或提交行为；其中某一步返回不代表 GPU 已完成。

GPU Fence 满足说明其同步协议覆盖的工作已达到相应设备进度点。Present 推进交换链呈现流程，可能涉及阻塞，但成功返回不证明整块面板已经显示新图。GPU 完成与 Present 调用不应被画成所有路径都固定“先 CPU 等 GPU 全完，再 Present”的关系。

## 题 2：索引与实例

在题设完整网格、三角形列表条件下：

```text
每实例索引数       = 12 × 3 = 36
基础索引范围字节数 = 36 × 2 = 72 byte
图元实例总量       = 12 × 4 = 48
```

四个实例可重复使用同一基础索引范围，不要求把索引数据复制四份。72 byte 没有包含分配对齐、其他缓冲或资产元数据。

Pixel Shader 工作还取决于几何投影、裁剪、覆盖、遮挡、深度测试、采样与硬件执行策略等，不能由三角形数或索引数直接计算。

## 题 3：绑定、状态与同步

描述符或绑定视图说明本次按什么格式、范围与方式访问资源。它不证明前次写入已经完成，也不会自动替代同步。

颜色附件写入后被计算 Shader 读取，在传统模型中需要从适用的写状态转到相应 Shader 读取状态，并满足相关访问可见性要求。资源本身还必须支持这些用途，创建能力和视图不能靠状态转换补造。

连续 UAV 调度即使使用相同 UAV 状态，也可能因写后读依赖需要 UAV 屏障或增强模型中的相应同步。若消费者位于另一队列，还要建立生产者信号与消费者队列等待，并按后端要求处理跨队列资源转换。CPU 调用先后顺序不能单独代替它们。

## 题 4：双队列算例

仍然以第一项工作在 `0 ms` 开始，忽略同步开销、提交开销和设备竞争：

```text
T 产生                  = 2 ms
Direct 独立工作结束     = 2 + 1 = 3 ms
Async 生成 U 结束       = 2 + 3 = 5 ms
Direct 组合开始         = max(3,5) = 5 ms
Direct 组合前的等待时长 = 5 - 3 = 2 ms
最终完成                = 5 + 1 = 6 ms
```

最终完成时间是 6 ms，Direct 在组合前等待 2 ms。队列允许表达并发工作，但实际重叠还受硬件执行能力、带宽与缓存竞争、调度及同步开销等因素影响。这些毫秒数是教学给定值，不是 UE 实测结果。

## 题 5：完成证据与屏障实现

正确 PSO 只覆盖相应管线配置，仍需正确资源、描述符、参数、访问声明、屏障与寿命。`WaitForSubmission` 等待提交推进，不能代替目标 GPU 工作的完成条件。

安全读回还需安排适用的复制与读回资源，在对应 GPU Fence 满足并遵守接口协议后访问 CPU 可读数据，同时处理格式和行跨度。Present 成功表示 API 呈现流程按契约推进，不提供面板全部像素已完成物理显示的证明。

本版同时有 Legacy 与 Enhanced 实现。源码偏好初始值为 Legacy，但实际使用应查启动日志中的 `Chosen Barrier Implementation`，并记录配置、构建与驱动条件。仅凭 D3D12、SM6 或源代码里出现 `Barrier` API，不能断定当前运行使用增强屏障。
