## 题 1：场景成员不等于主视图候选

不应仅因主相机视锥排除就删除 SceneInfo 或 GPU Scene 记录。方块仍属于渲染场景，之后可以重新进入画面，也可能服务阴影、反射和其他 View。可见性结果只针对指定的观察和工作范围，不是全场景生命周期判断。

位图为 true 也不保证最终贡献像素。它只说明尚未被当前检查排除；后续相关性、LOD、实例筛选、三角形裁剪、深度测试和材质处理仍会影响贡献，后处理及合成还会继续改变结果。

## 题 2：基础有效载荷与实际成本

```text
每条 = 44*16 = 704 字节
全量 = 8000*704 = 5,632,000 字节
本次 = 250*704 = 176,000 字节
减少 = 5,632,000-176,000 = 5,456,000 字节
本次占比 = 250/8000 = 3.125%
减少比例 = 96.875%
```

这只是按固定 primitive 布局计算的有效载荷。实例、payload、光源、顶点与索引、纹理、空闲容量、对齐、上传索引和临时分配均未计入，所以不是总显存。

性能还涉及 CPU 收集与打包、GPU 写入、固定调度成本、其他更新及瓶颈。一个 primitive 可以关联大量实例，不能把记录条数直接等同于总上传工作。有效载荷减少 96.875% 也不等于整帧快 96.875%。

本题还假定缓冲容量及布局无需引发额外全量更新。真实运行中，应检查本次进入的更新分支和上传数量，再决定该估算是否适用。

## 题 3：边界相交和球边缘距离

本节平面采用 `n=(-1,0,0)`、`d=300`，投影半径 `r=20 cm`。

```text
中心 x=325：s=-25，s+r=-5<0，整个盒子在外，可排除
中心 x=315：s=-15，s+r=5>=0，不能按该平面排除
```

第二个中心虽在外侧，盒子仍伸入内侧。通过这个平面还不保证通过其余平面，更不保证真实三角形覆盖像素。

球的最近距离为 `1200-150=1050 cm`，小于最大绘制距离 1100 cm，所以不因过远排除。中心距离法会得到不同结果，但不符合题目指定的球边缘条件；本题已经排除了渐隐、缩放及其他筛选的影响。

## 题 4：不同粒度的开关和结果

不能说明所有遮挡关闭。这两个值属于 GPU 实例筛选的相应控制，CPU primitive 遮挡、预计算可见性以及 Nanite 等路径有各自条件。

还应分清 HZB 的生成与用途：SSR 等消费者可要求生成 HZB，即使普通 HZB 遮挡没有启用，也不能由此推断该资源完全不存在。

将实例遮挡设为 1 仍需有效历史 HZB、适用上下文与 Shader 变体。单实例可能进入 UnCulled 桶，GPU Scene 支持也不能替代这些条件。因此不能只凭两个开关就宣布红方块已经执行某个测试。

列表缩为 3 个表示此次绘制工作只保留相应实例。其余实例可以继续存于 GPU Scene，下帧或其他 View 再使用；筛选不等于移除场景数据。真实输出顺序还取决于保序与原子写入方式。

## 题 5：三种依赖保护不同事实

本版场景更新通过 `PostStaticMeshUpdate` 回调启动可见性任务，再组织 GPU Scene 更新；并行准备条件下，相关性任务会成为上传准备的前置条件。CPU 可见性与上传准备可以按任务关系交错进行，C++ 函数返回不表示 GPU 已经完成上传。

CPU 任务依赖保护共享场景及准备数据何时可以安全读取；RDG 和后续资源同步保护 GPU 消费者何时能读到上传后的正确内容。二者都不能证明过去的遮挡结论仍适用于新视角。

相机突然切换后，原先的前景可能不再挡住方块。历史有效性规则必须使旧查询被忽略、重置或重新测试，源码的相机切换、时间和移动检查服务于这个目的。不能靠上一帧位图的真假替代当前观察条件。
