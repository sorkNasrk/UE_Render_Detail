# 第 04 章参考答案：Shader、材质与光照基础

[返回第 04 章](../../chapters/04-shaders-materials-lighting.md) · [返回总目录](../../README.md)

> 适用 UE 5.7.4，CL 51494982，配置 A。以下算例是正文约定的教学模型，不是实际 UE 抓帧数据。

## 题 1：一个材质与多个 Shader

同一个材质可能用于 Base Pass、阴影深度等不同任务，需要不同阶段或不同功能的程序。顶点工厂、平台、材质静态参数、Pass 类型及编译条件还可能产生不同组合。Shader Map 用于组织所需程序，不能把一个材质资产等同于一个 PS。

普通 Roughness 参数在父材质已经暴露且 Shader 支持的前提下，通常只改变运行时供程序读取的数据。Static Switch 可能改变需要保留的表达式与编译组合；已有结果可复用缓存，否则可能触发新编译。在 Cooked 程序中还要事先准备所需组合。

二者都不能直接证明稳定 GPU 耗时。编译耗时、PSO 准备耗时和 GPU 每帧执行成本是不同指标；是否发生等待也受缓存与异步处理影响。

## 题 2：归一化与 Lambert

朝光向量长度为 `sqrt(3²+4²)=5`，因此：

```text
L = (0, 0.6, 0.8)
NoL = max(dot((0,0,1), L), 0) = 0.8
E = 5 * 0.8 = 4 W/m²
Lo = (0.5, 0.25, 0.1) * 4 / pi
   = (2/pi, 1/pi, 0.4/pi)
   ≈ (0.636620, 0.318310, 0.127324) W/(m²·sr)
```

如果已知实际落到表面的 `E=4 W/m²`，则省去 `E_perp*NoL`，直接用 `rho*E/pi`。再乘 `0.8` 会重复计算表面投影。

该结果只包含假定的纯 Lambert 贡献，未加入镜面、其他灯、间接光、阴影、预曝光和输出转换。RGB 在这里作独立教学分量，不是把编辑器流明数值直接当成瓦特。

## 题 3：F0 与 Schlick

在传统非金属基础映射中：

```text
F0 = 0.08 * 0.5 = 0.04
Fc = (1 - 0.5)^5 = 0.03125
F = 0.04 + (1 - 0.04) * 0.03125 = 0.07
```

`F0=4%` 是正入射反射率，`F=7%` 是当前微表面角度下的 Fresnel 因子，不是最终亮度。还需结合微表面分布 D、遮蔽与几何换算、灯光及余弦等，随后还可能经过其他贡献累加、曝光和色调映射。

本地两参数 `F_Schlick` 的掠射项取 `saturate(50*F0.g)`。本题灰色 `F0=0.04` 使该项等于 `1`，与教学式一致；换成更低输入时不能无条件照搬结果。

## 题 4：金属、粗糙度与两种遮挡

传统基础映射的 `DiffuseColor=BaseColor*(1-Metallic)`。Metallic 增大使普通漫反射部分减小，Base Color 更多地用于镜面 F0。金属需要在适当方向获得直接光或环境反射；基础配置没有天空光、反射捕获或 GI，因此大片区域可能缺少可反射内容。提高 Base Color 不能生成不存在的入射光。

粗糙度改变微表面朝向分布：高光通常变宽，峰值分布改变。原先位于窄高光内的点可能变暗，原先高光外的点也可能变亮；有限光源、能量处理和反射算法还会影响结果。

BRDF 的 G 是微小表面之间遮蔽的统计项。阴影贴图估计场景中遮挡物是否挡住光源到当前点的传播。G 不能判断远处方块是否投影到地面上，阴影贴图也不能代替材质粗糙度导致的微观遮蔽。

## 题 5：透明 Unlit 与绘制输入

P 的方块可随点光增强而改变；Q 后面的方块也可能改变。即使蓝片的混合前颜色 `Csrc` 与 `alpha` 保持不变，简单透明关系仍为：

```text
Cout = Csrc * alpha + Cbackground * (1 - alpha)
```

背景变化会通过第二项改变 Q。它不证明 Unlit 薄片接受了直接表面光照。若曝光也变化，则还混入显示链变化，不能继续当成单变量实验。

Shader 程序说明怎样计算，但没有自动决定当前使用哪张纹理、哪组参数和哪个缓冲。绘制仍需要绑定程序输入，并设置适用的 PSO、顶点／索引资源与动态状态。录入 RHI 绘制命令只是执行链中的一个边界，也不等于 GPU 已完成或画面已经显示。
