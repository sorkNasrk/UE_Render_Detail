## 总览：先看清路线

### 题 1：为什么 Base Color 不等于 P 的屏幕颜色？

Base Color 是材质属性之一，描述表面响应所需的数据；它还没有结合灯光方向、强度、遮挡、其他光照贡献、观察方向以及显示变换。P 的颜色经过相关阶段才逐步形成，最后还可能受时序处理、曝光和色调映射影响。

例如保持红色参数不变，只让灯从另一侧照射，原先受光的面可能变暗。这不是引擎更改了材质的红色，而是相同表面属性在不同照明条件下得到了不同结果。

### 题 2：为什么 Q 的普通 GBuffer 不必保存薄片属性？

本例薄片使用 Translucent、Unlit 材质，走专门的透明处理。主不透明 GBuffer 需要保存后方可见方块的属性，以便形成背景颜色。随后薄片自己的颜色贡献与这个背景组合。

若把 Q 直接变成仅保存薄片的一套不透明属性，会丢失我们正在解释的背景关系。这个回答不覆盖所有自定义深度或特殊材质分支。

### 题 3：为什么 RDG Execute 返回不等于已经显示？

图执行会在 CPU 侧处理依赖、安排资源并调用记录命令的相关路径，后端还要提交工作，GPU 还要执行。主场景之后可能存在窗口绘制与另一个 RDG，然后才进入相关呈现流程。

即使调用了 Present，也仍需区分 GPU 对相关资源的完成状态、呈现系统安排和物理显示扫描。静态 C++ 返回位置不能测量这些事件之间的时间。

### 题 4：为什么 Base Pass 后生成阴影深度不必然错误？

本书的传统不透明 Base Pass 主要记录表面属性，并不要求先完成它后面要用到的所有直接光照阴影。只要读取阴影结果的工作在依赖满足后执行，阴影深度可以在允许的条件分支里较晚安排。

不能再反过来推广为“所有阴影都应放在 Base Pass 后”。真正的要求来自具体消费者、资源和配置；源码存在较早与较晚分支。

### 题 5：跨帧重叠是否说明固定一帧延迟？

CPU 可以在不需要等待所有已提交工作完成的情况下准备后续数据，GPU 同时消费已提交命令。稳定的数据所有权、资源生命周期和同步使这种重叠能够正确发生。

重叠量取决于线程与队列组织、负载、同步、帧节奏和呈现等因素，因此概念图不意味着固定一帧延迟。需要测量时，必须记录具体运行配置并使用适合的时间信息。

## 第 01 章：从场景到像素

### 题 1：相机或灯光改变，为什么图像变化？

相机决定三维位置怎样投影到屏幕，移动或转动后，可见面、覆盖位置和遮挡关系会改变；镜面响应也与观察方向有关。因此同一个屏幕位置可能换了观察对象，即便材质完全未变。

灯光方向改变后，表面与入射方向的关系、光线被谁挡住以及阴影投到哪里会改变。这些因素改变的是照明结果，不需要先修改 Base Color。

答案不能简化成“相机只改位置，灯光只改亮度”：视角能影响镜面响应，灯光也能改变颜色与阴影分布。

### 题 2：为什么三角形覆盖还不够？

| 概念 | 负责的主要问题 |
|---|---|
| 顶点数据 | 提供表面几何与属性，再结合变换确定图元位置 |
| 光栅化 | 产生屏幕覆盖与插值相关工作 |
| 深度测试 | 按同一深度约定判断候选表面相对已有表面的可见关系 |
| GBuffer | 在本书配置下记录可见不透明表面属性，供后续相关计算使用 |

方块和地面可以覆盖相同位置；单凭“覆盖”无法判断谁在前面，也无法决定最终光照颜色。测试、材质逻辑和后续颜色计算都还有自己的作用。真实 GPU 可以调整一些测试时机，因此该表不是硬件微观执行顺序。

### 题 3：计算透明混合颜色

采用题目指定的线性、非预乘 Alpha 模型：

```text
C_out = α × C_front + (1 - α) × C_back

R = 0.25 × 0.2 + 0.75 × 0.6 = 0.500
G = 0.25 × 0.4 + 0.75 × 0.2 = 0.250
B = 0.25 × 0.8 + 0.75 × 0.1 = 0.275

C_out = (0.500, 0.250, 0.275)
```

这只是所定义混合步骤的输出。真正场景的输入可能经过其他计算，输出还可能经过曝光、色调映射、时序处理与颜色编码。显示拾色通常得到的是某种最终显示表示，而不是本式中的线性中间值。

第一章正文另一组输入计算得到 `(0.5550, 0.2750, 0.3825)`。两组输入不同，不能混用。实践薄片的 `Tint × EmissiveStrength` 也不是这两组手算输入的实测来源。

### 题 4：添加 RDG Pass 后，GPU 是否完成？

不能。添加 Pass 通常是登记工作和资源关系。需要区分：声明图、处理依赖和资源、调用 Pass 执行路径记录命令、后端提交、GPU 执行，以及有需要时观察其完成。

CPU 已经运行完“添加”的那一行，并不能证明异步或后续阶段已经完成。即使采用某种调试模式提前处理图，也不能把“处理图”普遍等同于显示器已更新。

### 题 5：Opacity=1 与 Present 的两个边界

在本章简化公式中，Opacity=1 使输出完全采用前景颜色，但材质仍然是 Translucent、Unlit。混合模式、着色模型、深度行为和 Pass 分类没有因为这个数值自动变成 Opaque、Default Lit。

Present 是向相关显示系统请求呈现。调用、排队、GPU 完成以及屏幕刷新是不同事件；它们的关系要结合当前平台与同步配置解释。不能用函数返回来宣布物理屏幕已经扫描完毕。

## 如何判断自己可以进入下一章

不查看正文，尝试画出 P 的五类信息：场景输入、观察与覆盖、表面属性、颜色计算、输出。再在 Q 上增加前景与背景的组合，并指出哪一步的颜色可以拿来计算、哪一步不能直接当成屏幕值。

你不需要此时说出完整 Shader 名称。能明确这些信息来自哪里、为什么需要，已经具备进入坐标变换章节的基础。
