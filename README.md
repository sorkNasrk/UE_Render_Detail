# Unreal Engine 5.7 渲染管线：从场景到屏幕

这是一套面向初学者的中文教材。假设你能理解变量、函数、数组和对象，但还没有系统学习过计算机图形学。教材要回答的是：**游戏世界中的数据，怎样经过 CPU 和 GPU 的协作，变成屏幕上的一帧画面？这些工作又怎样落在 UE 的源码里？**

本书不要求你先背下渲染函数名。先理解问题和数据，再理解算法与执行关系，最后沿源码验证自己的理解。

## 学习路线

**必要的图形学基础 → UE 的场景与线程架构 → 一帧的组织与执行 → 各阶段的数据转换 → 现代功能分支 → 完整源码与观察案例。**

这条路线有意把“逻辑上需要哪些结果”与“机器上谁在什么时间执行”分开。知道阴影会影响光照，并不意味着 CPU 必须等 GPU 把阴影全部画完，才能开始编写光照任务。

贯穿场景始终包含摄像机、地面、红色不透明方块、金属球、透明薄片、方向光和点光源。我们持续追踪两个位置：不透明表面的像素 P，以及薄片覆盖下方物体的像素 Q。先研究静止场景，再加入运动和历史数据。

## 本书怎样使用证据

- **[源码已确认]**：在本地指定版本中查到了相应定义、调用或分支。它证明代码如何写，不自动证明你的机器实际走过该分支。
- **[教学简化]**：为隔离一个问题，省略已经声明的因素，或者使用虚构但可计算的输入。不是引擎的逐行实现，也不是实测图像数据。
- **[运行观察已验证]**：只有实际执行并记录了配置与观察结果，才使用这个标记。本批没有此类结论。
- **[尚未验证]**：例如观察练习的实际运行结果、硬件能力和 GPU 时序。本书会给出合理预期，但不会把预期写成已经发生的结果。

纯概念定义属于图形学基础知识；标记主要用于容易混淆的实现、图解、算例与运行行为。网络资料负责补充解释；遇到版本相关的调用顺序和设置行为，优先回到本地源码。

源码索引中的行号是本批定位时的行号。引擎更新后，先查版本，再按文件路径和符号搜索，不把旧行号视为长期不变的接口。

每章都以学习目标、前置知识、正文、案例、回顾和理解检查收尾。主要 Render Pass 的专章会统一说明“作用、原因、输入、过程、输出、实现、条件、成本与误区”；总览负责建立地图，不替代这些深讲。
